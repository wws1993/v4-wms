# WMS 保税仓储管理系统 — 项目设计

## 1. 项目概述

### 1.1 建设背景

广西丰联铜业有限公司为**铜精矿混矿企业**，需对保税货物仓储全流程实施数字化管控。当前物料仅有**铜精矿**一种，加工完成后产出仍为铜精矿（混矿/筛分等物理加工，不涉及物料品类变更）。

### 1.2 建设目标

面向保税物流园区的仓库管理系统（WMS），覆盖基础档案、入出库、移库、库存、生产流转、关务监管、OCR 识别与对外对接，支持原料/成品分区、保税账册对账与海关专用账号隔离。

建设主线（对齐采购文件与投标技术方案）：

1. **业务流程数字化**：入库—移库—盘点—生产—出库—关务核销全链路在线
2. **保税监管规范化**：海关专用账号隔离、账实自动对账、单证关联留痕
3. **库存管理精细化**：五仓多区、报关单号/生产批次号干湿重、库容与库龄预警
4. **运行环境自主可控**：本地自建服务器，信创软硬件适配
5. **项目交付可验收**：合同签订后 **55 个自然日**内完成开发、测评、部署与终验

### 1.3 仓储现场特征（业务约束）

| 特征 | 说明 |
|------|------|
| 仓库数量 | **5 个仓库**，每个仓库下设若干**片区** |
| 往来主体 | 委托方（五矿有色/广西金川/广西南国）、物流账册主体；**流向企业由出库报关单字段自动识别录入**；**不维护统一社会信用代码**；委托方贯穿出入库/移库/库存/生产全链路 |
| 保税账册 | 维护货值、报关单号及出入库票矿；**新账须填旧账预警日期**；旧账只出不进；超过预警日后未出库票的入库数据转入新账；列表可按**旧账预警时间范围**筛选 |
| 片区标识 | **原料区 / 待检区 / 成品区**；完工入库只允许进入待检区；查验完成后变为成品区。例：生产批次 FL-20260803 上架 4#A1 为待检区，查验完成改为成品区 |
| 批次号 | **仅两种**：① **报关单号**（原料/进口在库身份，入库上架后即库存批次，不另编系统号）；② **生产批次号**（混矿产出身份）。**同一生产批次号允许挂接多个报关单号矿物** |
| 物料品类 | **主做铜精矿**；档案区分原料/成品。原料货物类型为**达标矿/报备矿**（报备矿引用矿源，备案号入库自动匹配）；**成品货物类型一律为混成品**；品质参数属于上架后的本票库存；另维护干湿重、报关单、核注清单等 |
| 库存预警 | **库容预警**：片区占用达额定库容 **70%** 触发；**库龄预警**：原料在库超过 **90 天（3 个月）** 触发 |

### 1.4 对外对接边界

| 优先级 | 对接方 | 来源 | 说明 |
|--------|--------|------|------|
| 必预留 | **海关**（单一窗口/联网申报、电子账册核销） | 原始需求、采购文件 | 关务专用账号、申报回执归档 |
| 必预留 | **物流** | 原始需求 | 物流信息交换端口（提单、船名、到货等协同） |
| 扩展预留 | 园区辅助监管系统 | 采购文件、投标方案 | 监管数据上报 |
| 扩展预留 | 企业 ERP | 采购文件、投标方案 | 主数据/单据同步 |
| 扩展预留 | 生产系统 | 采购文件、投标方案 | 投料/完工数据协同 |

实施原则：先以接口清单和样例报文完成端口预留与模拟联调；对端条件未就绪时交付可配置端口、字段映射、调用日志和待办清单。

## 2. 业务模块

| 序号 | 模块 | 核心能力 |
|------|------|----------|
| 一 | 基础数据管理 | 仓库管理（1/2/4/5/6 仓及**码头仓库**；总库容；**面积㎡仅档案展示、可编辑，不参与占用计算**）、堆位管理（编码/片区标识/网格/库容；档案页不展示报关单号、生产批次、占用率、查验状态；**网格取自平面图堆位占格**，列表展示、新建/编辑弹窗不展示；入库预约须圈选存放位置）、物料档案（可导出 Excel；新建/编辑仅编码、名称、货物类型、类型，报备矿填矿源）、往来主体、保税账册、参数/权限/日志；**系统设置 · 平面图设置**绘制整个园区（网格密度为行×列，画板可缩放精细绘制；5 个启用仓库 + 1 停用仓库 + 1 办公楼 + 道路/灌木，仓库内嵌套生产线/门/堆位；仓库标号 4#、5# 等标在仓库下方居中，堆位名左下角且不含仓号前缀、**堆位背景白色、仓库默认 #f8e4c5、门默认 #9ebce9**，门/设备间/功能区等居中；**拖拽平移不改尺寸**；生产线/功能区名称随块缩放并可换行）；片区标识变更留痕见操作日志 |
| 二 | 入库管理 | 预约收货（船名、提单号、报关单、核注清单、金额、**矿种、装运方式（集装箱/散货）、集装箱柜数**、**预定堆位及平面图格子存放位置**；**预约与到货登记不含五项有害元素**）；列表可按**时间范围、货运方式、矿种**筛选；状态为**暂存码头 / 待收货 / 已入库 / 混成品**（列表不含片区标识）；报备矿按矿源自动匹配备案号、OCR 品质单、称重干湿重、账册匹配；上架后**原料库存批次取报关单号** |
| 三 | 库内移库 | 先选原堆位再选矿批次；**委托方/报关单号/生产批次/物料/船名/柜数只读表格带出**；批量移库**可跨仓勾选**并查询，**每票一条记录不合并**；列表可按**委托方、时间范围**筛选；移库时间为**起止到时**（不含分）；列表无操作人/详情 |
| 四 | 库存精细化 | 多维查询（矿源/账册/原料成品/堆位/片区标识/时间：本月或起止精确到时；**列表不含类型列**）、货物类型：**原料达标矿/报备矿、成品混成品**、本票品质为 Cu/Ag/Au/As/Pb/Cd/F/Hg **八项**、**成品原产国为 —**、**已出库堆位为 —**；本票详情含报关单/重量证书/品质证书及**成品去向**（产量、库存、出库）；重量台账出库流水记**流向企业**；**盘点无类型字段，范围可多选仓库/堆位，可上传附件，不回写库存、不生成账实差异**；**盘点可按月份导出各委托方在库数量、堆位、货物类型、提单号、报关单号**；库容与库龄预警、**码头仓库货品超 7 天（可配）预警** |
| 五 | 生产/完工流转 | 按**生产批次号**投料出库，**同一生产批次号可勾选多个报关单号矿物**；投料记录含**出库报关单号**；**物料、船名/航次、提单号、来源国家在详情展示**；**投料出库与加工过程合并为一项**，可按**委托方、时间范围**筛选；矿物按**达标矿/报备矿**展示；**完工入库只允许进入待检区**，**查验完成**后堆位片区标识改为**成品区**；成品完工入库后库存批次即该生产批次号；谱系追溯至各报关单号 |
| 六 | 出库管理 | 出库订单审核、**OCR 识别出库报关单**回填报关单号/核注清单号、流向企业、**消费使用单位**、出库时间、重量与**报关单金额**；列表可按**时间范围**筛选；**出库台账记录流向企业**；OCR 字段可手工修正并留痕；备注选填 |
| 七 | 关务保税监管 | 海关账号隔离、账实对账、差异穿透与报表导出、联网申报与核销预留 |
| 八 | OCR 单据识别 | 报关单（入库/出库）/提单/品质/重量单识别回填；**全部识别字段可手工修正**，修正写入操作日志（修改前后值）；附件归档 |
| 九 | 对外对接 | 海关、物流（必预留）；园区监管、ERP、生产系统（扩展预留）；白名单/HTTPS/幂等/重试 |
| 十 | 安全与留痕 | 操作人/时间/内容/修改前后值**永久留存**（不提供年限配置） |
| 十一 | 可视化驾驶舱 | 科技风 HUD：放大的五仓拼接园区平面图（**默认整园**；**卫星图开关**切换航拍屋面/堆场风格；点击仓库/堆位**仅绘制该仓**，放大后点堆位进管理、点矿物进库存，左上角回退；堆位格子货物/预约；关闭卫星图时**仓库/生产区/堆位填色与平面图设置一致**；在库矿物按货主分色：南国铜业绿、五矿有色黄、广西金川蓝，达标矿浅、报备矿深，混成品灰；**加载中显示工业风扫描至少 2 秒，不闪默认图**）、入出库趋势（湿吨）、加高的作业链路日志滚动（时间到年月日时）、生产数据卡片、**仓库使用分布**（各仓占用进度条）、预警（无缝循环滚动、悬停暂停）；指标可下钻至报关单号/生产批次号/单据/日志 |

### 2.1 模块控制原则（投标/采购对齐）

- **业务规则校验 → 岗位权限控制 → 审批流转 → 库存实时记账 → 全过程留痕 → 汇总穿透查询**
- 库存余额由已审核业务流水汇总，禁止脱离单据直接改数；盘点只归档现场资料，不调整账面
- 海关专用账号在操作日志中单独标识；关务员菜单默认全开
- 移库在同一事务内扣减原堆位、增加目标堆位库存，目标堆位片区标识随在库批次（报关单号或生产批次号）状态更新；任一步失败整体回滚

## 4. 关键业务对象

- 仓库（1/2/4/5/6 仓，仅编号；**码头仓库**按名称；含总库容与**面积㎡**，面积仅展示不参与占用）/ 堆位（物理货位编码，如 1#A1、5#大A前、码头#A1）/ 片区标识（原料/待检/混成品等区域属性，随在库批次查验变更）
- **批次号（仅两种，禁止第三套系统批次号）**
  - **报关单号**：原料在库、移库、投料、库龄、关务对账的身份；入库上架后直接作为库存批次
  - **生产批次号**：混矿/筛分产出的成品在库身份；完工入库不另生成成品批次号
  - **1:N**：一个生产批次号可包含多票报关单号矿物；投料、加工、完工均按此挂接并保留谱系
- 铜精矿（原料/成品状态；原料货物类型达标矿/报备矿，**成品一律混成品**）、**矿源**（报备矿引用；备案号入库时自动匹配；**矿源备案维护原产国、附件与关联生产批次号，列表可按备案日期时间范围筛选，备案编号可查看并导出该备案下全部票货**）、本票品质参数（上架后记 **Cu/Ag/Au/As/Pb/Cd/F/Hg 八项**；成品原产国不填）、干湿重
- 往来主体（委托方、物流账册主体；**下游流向企业由出库字段自动识别录入**；**不含统一社会信用代码**）
- 保税物流账册（**货值、报关单号**；保存出入库票矿，账册编号可查看并导出；**新账衔接旧账须填预警日期，旧账只出不进，到期未出库入库数据转入新账**）
- 入库单 / 出库单 / 移库单 / 盘点单 / 生产工单
- OCR 识别任务与附件归档
- 预警规则（库容 70%、原料库龄 90 天、**码头仓库货品超 7 天**、**旧账册预警日后未出库票转入新账**）
- 操作审计日志（含修改前值、修改后值、来源地址、关联业务单号）
- 接口配置与联调日志（海关、物流、园区、ERP、生产）

## 7. 技术建议（后续开发）

- 前端：**Vue 3 + TypeScript + Element Plus + Vite**，工程在 `frontend/`。后端接口未就绪时默认本地 mock（`VITE_USE_MOCK=true`），响应格式仍为 `{ success, data, message }`。页面不包含对外对接、开发进度跟踪、系统架构。
- 后端：**Java（Spring Boot）** + **海量数据库（Vastbase，PostgreSQL 兼容）** + MyBatis-Plus / Spring Data JPA + Flyway + JWT
- 分层：`controller`（入参校验）→ `service`（业务）→ `mapper/repository`（数据访问）；统一响应 `{ success, data, message }`
- JDK：以信创适配清单锁定（优先 LTS，如 17；若客户清单仅有 8/11 则从其规定）
- 运行环境（正式/验收）：**统信服务器操作系统（UOS Server）**（采购文件亦允许银河麒麟 V10，以投标承诺为准）
- 数据库：海量 Vastbase（采购文件亦允许达梦 V8.4，以投标承诺为准）
- 必须满足：**信创适配认证**、**网络安全等级保护（等保）二级及以上**

## 8. 信创与等保硬约束

### 8.1 目标运行环境

| 项 | 要求 |
|----|------|
| 操作系统 | 统信服务器操作系统（UOS Server），按客户指定版本/补丁基线 |
| 数据库 | 海量数据库 Vastbase（信创名录范围内版本） |
| CPU 架构 | 以客户机房为准，投标方案为鲲鹏 920（32 核）；**开发与验收需按实际架构验证** |
| 中间件 | Nginx/OpenResty 等需使用客户或信创清单允许的发行包；**JDK** 版本以适配清单锁定 |
| 容器 | 不以 Docker 为默认前提；部分信创机房禁止或限制容器，需同时具备 **systemd 裸机部署**方案 |
| 服务器硬件 | 采购基线：≥8 核/≥2.6GHz、≥32GB ECC、系统盘≥480GB SSD、数据盘≥960GB SSD、硬件 RAID（2GB 缓存+电容）、双冗电源风扇；投标方案高于基线（128GB、2TB NVMe RAID1 等） |

### 8.2 开发阻碍清单（落地重点）

以下为正式开发相对「通用 Linux + MySQL/PostgreSQL」会增加的阻力点，排期与选型时必须计入。

#### A. 操作系统与运行时（统信 UOS Server）

| 阻碍 | 说明 | 影响面 |
|------|------|--------|
| 开发机与验收机不一致 | 日常开发多在 Windows/Mac/Ubuntu；问题常到 UOS 才暴露（依赖库、glibc、OpenSSL、证书路径） | 联调、发版、缺陷复现周期变长 |
| 软件源与依赖包缺失 | apt 源与社区 Debian/Ubuntu 不完全一致；部分 JNI/本地库、字体、图像编解码库需在 UOS 上补齐 | OCR JNI、Excel/PDF 导出、本地字体 |
| CPU 架构绑定 | 鲲鹏/飞腾为 ARM；须使用对应 arch 的 JDK 与原生 SDK；无 aarch64 包的 OCR/驱动不可用 | OCR、导出组件、监控 Agent |
| 运行时版本受控 | 客户锁定 **JDK 大版本**；随意升级 Spring Boot/依赖会被适配验收打回 | Maven/Gradle 依赖树、安全补丁策略 |
| 容器受限 | 禁用 Docker 时，需改写部署脚本、进程守护、日志轮转、零停机发布 | 运维脚本、CI/CD、部署文档双轨 |
| 驱动与外设 | 扫枪、摄像头、高拍仪、打印机驱动需在 UOS 实测 | 入库现场采集、OCR 拍照链路 |

#### B. 数据库（海量 Vastbase）

| 阻碍 | 说明 | 影响面 |
|------|------|--------|
| 方言差异 | 基于 PostgreSQL，**不可按 MySQL 习惯**写 SQL/迁移；部分 PG 特性/扩展在 Vastbase 上需确认开启 | Flyway 脚本、MyBatis XML、报表 SQL、库存对账 |
| 驱动与 ORM | 使用 **PostgreSQL JDBC**（或厂商提供的 Vastbase JDBC）；Hibernate/MyBatis 方言按 PG；禁止 MySQL 驱动 | 工程初始化即定 PG/Vastbase 路线 |
| Oracle 兼容层干扰 | 若开启 Oracle 兼容模式，标识符大小写、空串与 NULL、日期函数行为可能变化 | 联调须固定「兼容模式开关」写入环境基线 |
| 工具链薄弱 | 备份恢复、慢查询、权限审计、主从切换依赖厂商工具与培训，社区资料少于 MySQL | 运维成本、交付手册、故障响应 |
| 迁移与授权 | 安装介质、License、连接数/实例规格常与商务绑定；开发库也需合规授权 | 本地/测试环境能否完整复现 |
| 性能画像不同 | 复杂对账、多维库存查询需单独压测；连接池、vacuum 等价运维参数与 PG 类似但不完全等同 | 盘点高峰、账实对账报表 |

#### C. 第三方组件与业务能力

| 阻碍 | 说明 | 影响面 |
|------|------|--------|
| OCR 信创适配 | 开源/商业 OCR 不一定提供 UOS + 目标 CPU 包；无包则只能换厂商或改为可审计的远程识别服务（仍需过安全评估） | 模块八整条链路 |
| 国产密码与通信 | 等保/信创常要求 TLS 套件、国密算法（SM2/SM3/SM4）可选或必备；须选用支持国密的 JDK 扩展/中间件，并在 UOS 上实测 | 登录、对外对接、HTTPS 终结位置 |
| 对接海关/物流/园区 | 对方多为信创区网；协议、专线、白名单、双向证书与我方栈要一起适配 | 模块九、联调窗口依赖对方 |

#### D. 等保带来的开发约束（与信创叠加）

等保（通常二级或三级，以定级为准）不只是上线前扫描，会反向约束设计和编码：

| 阻碍 | 开发侧要求 |
|------|------------|
| 身份鉴别 | 强密码策略、登录失败锁定、会话超时、必要时空双重认证；海关专用账号独立体系已在需求中，须与等保账号策略对齐 |
| 访问控制 | 前后端双重鉴权、最小权限、接口级权限；禁止仅靠前端藏菜单 |
| 安全审计 | 操作日志「谁、何时、何对象、何内容、改前改后」永久可查；日志防篡改、独立存储或周期性归档；管理员操作也要审计 |
| 通信与存储保密 | 传输加密（HTTPS/专线）；敏感字段（证件、账号密钥）加密或脱敏；备份加密 |
| 入侵防范与恶意代码 | 依赖漏洞扫描、上传文件类型/大小校验、防路径穿越；生产禁止危险调试接口 |
| 数据备份恢复 | 提供可演练的备份恢复方案与 RPO/RTO；海量库备份脚本纳入交付 |
| 安全分区 | 应用、数据库分区分域；对外对接置于 DMZ/指定交换区；开发环境不得直连生产库 |
| 等保测评配合 | 需出具拓扑、资产清单、权限矩阵、日志样例、漏洞整改报告；开发人员要预留整改窗口 |

#### E. 工程协作与认证流程阻碍

| 阻碍 | 说明 |
|------|------|
| 双环境并行成本 | 「开发便利环境」与「UOS + 海量验收环境」必须并行，否则末期集中适配风险极高 |
| 认证材料与版本冻结 | 适配认证要求软硬件版本清单；通过后随意升级中间件/JDK/Spring Boot 大版本可能需重新说明或复测 |
| 厂商支持响应 | 统信/海量工单时效影响排障；关键路径问题应提前建厂商支持渠道 |
| 人员技能 | 团队需具备 Java/Spring 与 Vastbase（PG 系）经验；若以往以 MySQL 为主须预留培训与试错时间 |
| 商务前置 | 系统盘、数据库授权、CPU 型号未定前，架构与 OCR 选型无法最终冻结 |

### 8.3 开发规避原则（强制）

1. **后端固定为 Java（Spring Boot）**；数据库按 PostgreSQL 方言 + Vastbase JDBC 设计；禁止引入 MySQL 专有 SQL/函数与 MySQL 驱动。
2. **所有含 JNI/本地库的依赖（含 OCR）必须在「目标 UOS + 目标 CPU + 目标 JDK」验证通过后再纳入主分支。**
3. **部署交付同时准备**：Compose（若允许）与 systemd + Nginx 裸机两套（`java -jar` 或同等方式）；等保拓扑按裸机/分区描述为准。
4. **审计日志、权限、密码策略、会话管理作为 1 期骨架能力**，不放到上线前补做。
5. **对外对接与国密/证书需求在接口设计阶段确认**，避免后期推倒重来。
6. **1 期结束前完成「最小信创冒烟」**：UOS Server 部署 Java 应用 + 连接 Vastbase + 登录/审计/一次入库主流程。

### 8.4 风险与缓解（摘要）

| 风险 | 缓解 |
|------|------|
| 末期才上 UOS/海量导致大面积不兼容 | Sprint 内固定信创联调环境；CI 增加目标架构构建任务 |
| OCR 无信创包 | 早期做 POC：2–3 家信创 OCR 或「边缘采集 + 集中识别」方案比选 |
| 等保整改拖期 | 安全需求进 Definite Scope；预留不少于 1 个迭代的漏洞整改 buffer |
| 客户禁止容器 | 不以 Docker 为唯一交付物；安装脚本与回滚手册同步维护 |
| 数据库授权不全 | 合同明确开发/测试/生产实例授权；本地可用开源 PostgreSQL 做功能开发，合并前必须在 Vastbase 回归 |
| 片区标识变更导致历史数据混乱 | 片区标识变更保留历史快照；库存流水记录变更时片区标识 |
| 55 日工期紧 | 按五批交付并行准备部署/培训材料；外部接口未就绪时以模拟报文验收端口 |

### 8.5 与本期原型的关系

0 期 HTML 原型不承载信创运行时验证。自 **1 期工程初始化**起，技术选型与仓库规范按本节执行；信创/等保适配工作列入开发计划专项，不得仅作为「上线」附属项。
