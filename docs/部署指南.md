# 部署指南

## 0期原型 — Docker 部署（当前推荐）

域名：`wms.skd.wang`  
部署目录：`depoly/`（含 `dist/`、`nginx.conf`、`docker-compose.yml`）

### 1. DNS

在域名解析里增加 A 记录：

| 主机记录 | 记录类型 | 记录值 |
|----------|----------|--------|
| wms | A | 你的 ECS 公网 IP |

解析生效后可用：`ping wms.skd.wang` 验证。

### 2. 阿里云安全组

放行入方向 **TCP 80**（后续 HTTPS 再放 443）。

### 3. 上传并启动

将整个 `wms`（或服务器上的 `depoly`）目录上传到服务器，例如 `/root/wms/`：

```text
/root/wms/
  docker-compose.yml
  nginx.conf
  dist/                 # 静态原型，可用 XFTP 整目录覆盖
  api/                  # 只放代码，可用 XFTP 覆盖；不要覆盖 data
  data/                 # 批注 + 平面图 JSON，与 api 分开，禁止用本地文件覆盖
```

日常用 XFTP 更新：见同目录 [`XFTP上传说明.txt`](../wms/XFTP上传说明.txt)。本地可运行 `wms/pack-xftp.ps1` 生成不含数据的 `xftp-upload/`。

服务器上执行（**不要再 `docker compose build` 拉 node 镜像**）：

```bash
cd ~/wms

# 1) 批注 API：系统 Python 常驻
python3 --version   # 需 3.7+
mkdir -p data
# 若目录不是 /root/wms，先改 api/wms-anno-api.service 里的路径
cp api/wms-anno-api.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now wms-anno-api
curl http://127.0.0.1:3000/api/health

# 2) 静态站：只用已有的 nginx:alpine（不再 build api）
docker compose up -d
docker compose ps
curl -I http://127.0.0.1:8081/
curl http://127.0.0.1:8081/api/health
```

临时前台调试 API（不用 systemd 时）：

```bash
cd ~/wms/api && bash start.sh
```

先用端口访问：`http://服务器公网IP:8081`  
（安全组需放行 **8081**）

### 4. 若报错 `port is already allocated`（80 被占用）

当前 `docker-compose.yml` 已改为 **`8081:80`**，先启动 WMS，再让占用 80 的服务按域名转发过来。

```bash
# 看谁占了 80
docker ps --format 'table {{.Names}}\t{{.Ports}}\t{{.Image}}'
ss -lntp | grep ':80'

# 启动 / 重启 WMS
cd ~/wms
docker compose down
docker compose up -d
```

**已对接易手办入口：** `E:\code\__self\v2-second-app\deploy\nginx.conf`  
原因：原配置 `server_name ... _` 会吞掉所有域名（含 `wms.skd.wang`）。  
现已改为：主站只认 `skd.wang` / `www.skd.wang`，并新增 `wms.skd.wang` 反代到宿主机 `8081`。

服务器上更新易手办部署目录后执行：

```bash
# 1) 确认 WMS 在 8081
cd ~/wms && docker compose up -d && curl -I http://127.0.0.1:8081/

# 2) 重载易手办 Nginx（目录按你服务器实际路径）
cd /path/to/v2-second-app/deploy   # 或服务器上的 deploy 包目录
docker compose -f docker-compose.prod.yml up -d nginx
# 或仅重载配置：
docker exec yishouban-nginx nginx -s reload
```

访问：`http://wms.skd.wang` → 易手办 Nginx(80) → WMS(8081)  
主站：`http://skd.wang` 仍为易手办。

### 5. 常用命令

```bash
docker compose logs -f web
docker compose restart web   # 改了 nginx.conf 后
systemctl status wms-anno-api
journalctl -u wms-anno-api -f
docker compose down
```

批注 / 平面图数据目录：**`~/wms/data/`**（`annotations.json`、`floor-plans.json`）。不要把本地 `api/data` 覆盖到线上。覆盖 `api` 后请 `systemctl restart wms-anno-api`；首次请把 `api/wms-anno-api.service` 拷到 systemd（数据目录已改为 `/root/wms/data`）。

### 6. 注意

1. DNS：`wms` A 记录指向 ECS 公网 IP；要域名直达需 80 反代或独占 80。
2. 当前为 HTTP；HTTPS 可后续加证书 / Caddy。
3. 本机用 Docker，无需再装系统 Nginx（除非用系统 Nginx 做统一入口）。
4. 批注同步依赖宿主机 `wms-anno-api`（Python）；若侧栏显示「离线缓存」，检查 `systemctl status wms-anno-api` 与 `curl http://127.0.0.1:3000/api/health`、`curl http://127.0.0.1:8081/api/health`。平面图：`curl http://127.0.0.1:3000/api/floor-plans` 与 `curl http://127.0.0.1:8081/api/floor-plans` 均应为 JSON（`success` + `data.plans`），不能是 HTML。浏览器保存平面图若出现 `ERR_CONTENT_LENGTH_MISMATCH`：覆盖 `server.py`、`nginx.conf`、`dist` 后 `systemctl restart wms-anno-api` 且 `docker compose restart web`。入口 Nginx 不要对 `/api/` 做 gzip（或尊重 `Cache-Control: no-transform`）。

## 本地预览原型（开发用）

```bash
cd wms/dist
npx serve .
# 或
python -m http.server 8080
```

本地打开时原型批注与平面图会请求线上 `http://wms.skd.wang/api/`，与线上共用同一份数据，无需再起本地批注服务。

## 后续正式环境

### 验收/生产硬约束（信创 + 等保）

正式交付与客户验收环境以以下为准（详见 `项目设计.md` §7）：

| 层级 | 选型 |
|------|------|
| OS | 统信服务器操作系统（UOS Server） |
| DB | 海量数据库 Vastbase |
| 应用 | **Java（Spring Boot）** 后端 + Nginx 静态/反向代理（JDK/中间件版本锁定在适配清单） |
| 进程 | 优先 **systemd** 托管 `java -jar`；Docker 仅在客户允许时使用 |
| 安全 | HTTPS/专线、分区部署（应用与库分离）、审计日志独立留存、备份可演练 |

**开发自测**可用通用 Linux + 开源 PostgreSQL 加速，但 **合并发布前必须在 UOS + Vastbase 回归**。

### 其他可选环境（仅内部原型/演示，不可替代信创验收）

1. **快速演示**：Vercel + 托管 PG（不可用于信创/等保验收）  
2. **自托管草稿**：Docker Compose（Nginx + Java + PostgreSQL）  
3. **通用云主机**：Linux + Nginx + systemd/Java + RDS  

部署前检查：测试通过、构建成功、环境变量、迁移、资源优化、备份；**信创环境另检**：目标架构 JDK 齐全、Vastbase 连接与权限、systemd 单元、等保分区与日志路径。

### 信创部署注意（摘要）

1. 先锁定 CPU 架构（x86_64 / aarch64）与 **JDK 版本**，再安装应用与含 JNI 的依赖。  
2. 应用使用 PostgreSQL/Vastbase JDBC；勿使用 MySQL 驱动。  
3. 同时维护：`docker-compose`（可选）与 `systemd` unit + Nginx conf（验收主路径）。  
4. 数据库备份/恢复按海量官方工具编写，并做至少一次恢复演练记录（等保常用证据）。  
5. 对外对接网段、防火墙白名单、证书与客户网安方案一致后再切生产。

## 一台服务器跑两套站点

**结论：可以。** 同一台机可跑多个 Docker Compose 项目，用不同域名或不同端口区分。

- WMS：`wms.skd.wang` → 本目录 compose（80）
- 其他系统：另起容器映射 `8080`，或前面再加一层反向代理按域名分流

若两个站点都要占 80，需统一入口（一个 Nginx/Caddy）按 `server_name` 转发到不同容器。
